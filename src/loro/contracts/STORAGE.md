# Storage contract C0.1

C0.1 changes storage only; Transport and ExchangeFrame remain unchanged. S1 fixtures model older shapes, and S2 adapters, L1 runtime and domain/Chef consumers must adopt this contract before integration. This contract does not select a cryptographic suite or establish native runtime proof.

All identities are scoped by `scopeId` and by their namespace (operation, command, effect, document, object, inbox item and receipt). The local command array is one operation/effect group, identified by operationId; command and effect IDs are individually unique. `storageOperationKey` defines exact equality for the complete input, including expected revisions, byte contents, associations and ordered arrays; it is an internal comparison representation, not a wire format or hash. Persist the complete representation or an equivalently collision-free comparison, not an unverified hash alone. Local and import operation namespaces are distinct. Inputs must pass validation before any write. Documents are ordered strictly by documentId and unique; other arrays retain order and IDs within each namespace are unique. Bounds are provisional, per operation; excessive byte or item counts return TOO_LARGE, malformed shapes return MALFORMED.

In one database transaction, first look up the scoped operation identity. If a completed operation exists, compare its entire input; exact equality returns the original saved revisions with replayed=true, even if the expected revisions are now stale. Otherwise conflicting identity reuse returns CONFLICT with zero writes. An incomplete or partial pre-existing set of operation, command, effect or object identities is a conflict, never a successful replay. Any reused identity with different bytes or associations is a conflict. For a new operation compare all expected revisions in the same transaction as all writes. Null requires absence and creates revision 0; an existing matching revision increments by one. A revision at MAX_SAFE_INTEGER cannot be updated. Any mismatch or failure leaves all documents, effects, immutable objects, outbox and operation record unchanged; caller reloads durable state. Cross-tab/process exclusion must come from database transactions, not an in-process mutex. Authority is revalidated by the caller before every invocation, including retries.

Stage inbox object bytes and cursor in one transaction. Cursor comparison is exact string equality, with null meaning absent; cursors are opaque and never ordered. Existing identical staged bytes may be reused, but differing bytes for the same scoped object ID conflict. A failed cursor comparison makes no writes. Import refers to an existing staged item, atomically writes all documents, effect IDs and its applied outcome, and preserves staged bytes on failure and success. Import replay follows the same complete-operation rules; an item already applied by a different operation conflicts. Storage does not verify authenticity.

Outbox entries and immutable effect/operation history survive receipt recording. Record receipt identities idempotently with exact field and byte equality; conflicting reuse writes nothing. Track each destination and recipient independently. Relay stored and peer stored/applied are distinct; peer applied requires a prior peer stored receipt for that object and recipient, and no transition regresses. A receipt is untrusted until verified by a higher layer. Receipt persistence never authenticates it, deletes an outbox entry, or implies delivery to another recipient. Queue selection may use these persisted states; deletion/retention policy is outside this contract.

Pure validators return typed errors and never create `Verified` values. Contract tests establish shape and equality only: database atomicity, crash recovery, quota mapping and concurrency require real adapter tests.

# Candidate own-adult device admission

This patch depends on the already integrated `candidate-v2.mjs`, `durable-session.mjs` and `key-package.mjs`. It keeps the original `candidate.mjs` intact. `personalAdmissionBytes` binds the pinned parent snapshot, sponsor, one existing owner, recipient, the recipient public key bundles, peer ID, transcript hash and guard. New-device key references are required to equal the lowercase hexadecimal public keys; the application's key resolver must support this convention.

`openPersonalPairing` requires independent local session evidence and pinned personal authority. Its sponsor `release(operationId, localKeys, keyOperation, keyIdentity, peerId)` returns `{release, admission}`. The authenticated envelope must be transported intact to the recipient. `install(envelope, recipient, master, masterId, keyRef)` checks the same evidence and commits the wrapped key, signed receipt and signed authority successor together. Release and installation are separate local transactions. Each transaction compares durable authority and commits its corresponding records together. Exact retries require the saved successor still to be current; changed authority requires a new ceremony.

`TransactionalStorage.commitPersonalAdmissionRelease` and `RecipientRecords.installPersonalAdmissionAndReceipt` are structural transaction seams, not signature verifiers: only call them after the personal admission verifier. Both share the existing `pairing-guard` namespace with projection publication. The patch leaves projection guard and source revision/owner checks intact. Household admission remains unavailable without its separate authority verifier.

Run the Node tests using `agent-heavy -- node --test src/loro/authority/personal-admission.test.mjs src/loro/pairing/personal-atomic.test.mjs`. For IndexedDB/WebCrypto, run `agent-heavy -- node src/loro/pairing/personal-browser-server.cjs` and evaluate `(await import('/browser-personal.mjs')).run()` in an isolated browser at localhost:19375. The fixture uses separate databases in one browser process and deletes them. It does not prove isolated browser providers, native secure master, Hermes, ARM or iOS.

## Settings personal device pairing

In Settings, an already authorized personal device can pair an independently created device for the same personal owner. Each device confirms the other device’s fingerprint, the source workspace’s root pin, and the matching transcript code separately from the transferred messages. The durable challenge uses both signing and wrapping key pairs. Settings shows the authorized and retired devices from the verified signed history and identifies the current device. The receiving device installs and selects the verified personal copy, then explicitly reopens the workspace. Its own original personal workspace remains available in Settings.

The version 1 pairing file is the sender’s 64-byte signature followed by a sealed box for the confirmed recipient wrapping key. The signature covers a domain-separated commitment to the exact transcript and ciphertext. The payload carries the verified v1, v2 or v3 parent history, the signed admission and existing recipient key package, and the personal document’s ID, generation, epoch, revision, frontier and byte commitment. The file limit is 7 MiB and the snapshot limit is 2 MiB. The saved personal snapshot can include Chef conversations, proposals and preferences. Provider credentials remain in their separate device store.

The publication transaction compares the exact authority record, personal selection, and source revision, owner and bytes. It stores the sealed file with the guarded release and signed successor, so restart can return the same bytes. The receiving transaction can claim an absent personal scope after verifying the offered parent in memory. It commits both local-key indexes, the wrapped-key receipt, document and owner, semantic indexes, selection, and signed successor together. The receipt binds the exact file. A retry checks the durable successor, installed key and receipt, semantic indexes and containment of the installed snapshot in the latest copy. A retry can reselect the paired copy from the receiver’s original workspace. The browser and native adapters use the same transaction logic.

The later household same-adult route requires its own current household parent and active device-to-adult proof, a signed same-adult transition, and explicit household key release and selection. Its proof must cover an unchanged electorate and unchanged vote weights. Personal pairing establishes only personal authority.

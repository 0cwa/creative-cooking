# Provisional transport adapter

This is a C0.1 preparation, not a frozen C1 wire format or an E1 result. The JSON/base64 encoding represents the C0 objectChunk fields. Frames are limited to 16 KiB, chunks to 8 KiB, encoded envelope objects to 2,425,344 bytes, and eight incomplete transfers. The latter two limits bound pending payload bytes to 19,402,752; this is not a bound on peak memory or storage representation. A caller retains the reassembler across channel reconnections and resends missing chunks; a page restart loses incomplete chunks. No inventory protocol or delivery service is implied.

The browser caller must authenticate the final manual signaling transcript against a previously accepted peer before attaching a channel. This module does not implement pairing or verify signaling. `sendFrames` accepts an open RTCDataChannel and handles buffered-amount backpressure. Received complete bytes must pass an actual candidate-envelope verifier whose returned ID and scope are checked by the caller. `stage` atomically stores those immutable bytes with the source cursor before signing a stored receipt. The runtime owns import; `applied` checks its durable import record before signing. The receipt provider must use configured peer signing keys and verify the identity and claims; `acceptReceipt` verifies first and only records peer receipts. Storage itself does not authenticate receipts. File export expects an already encrypted envelope, and file import remains untrusted until the same stage path verifies it. Native returns UNAVAILABLE pending a qualified binding.

The candidate codec accepts plaintext up to 1 MiB and its encoded envelope has a separate 2,425,344-byte storage limit. The existing T1 evidence uses an explicit local IPv4 substitution for mDNS candidates and authenticating the final descriptions remains a caller requirement. T1's Brave download/re-upload proof is spike evidence only; this adapter has not yet been proven with a browser download, real direct channel, app runtime, Android, or a restart. No account, relay, STUN/TURN server, or background delivery is required or promised by this adapter.

Browser proof on 2026-11-17: `agent-heavy -- node src/loro/transport/browser-server.mjs` served the isolated harness to a background T3 preview. Two peer connections in one page used no ICE servers. Each final signaling description was signed after replacing mDNS candidate names with the checked host IPv4 and verified against its independently generated, preaccepted test public key. This is an isolated test identity, not a human pairing implementation. Two real connections exchanged a 40,568-byte candidate envelope; frame 4 was delivered twice before disconnect, then frames 3, 2, 1 and 0 after reconnect. IndexedDB rejected an injected staging failure before any receipt, then staged and reopened the envelope, and an Ed25519 stored receipt verified. The negotiated SCTP maximum reported 262,144 bytes; frames remain limited to 16,384 encoded bytes. The receiver remained alive across reconnect. The small test did not induce real congestion; a unit test covers the backpressure event path.

For the genuine file proof, T3 preview's download click timed out and its download list remained empty. An isolated Brave Flatpak under `agent-heavy -- agent-headless` with a scratch profile and CDP then ran `agent-heavy -- env T2_SCRATCH=<scratch> T2_CDP=http://127.0.0.1:19236 node src/loro/transport/browser-file-proof.mjs`. Playwright saved the browser download (54,188 bytes) to disk and uploaded that path; the adapter reopened and authenticated the 40,568-byte candidate envelope. This is same-host browser evidence, not E1, cross-device or native proof.

The reassembler retains at most eight completed-transfer records with at most 297 SHA-256 chunk hashes each, plus bounded IDs and metadata; no complete payload is retained. Matching late chunks are ignored and changed bytes or associations conflict while the record remains in that window. Completion records are evicted oldest first when a ninth transfer completes. Incomplete transfers and completion records expire after five minutes of inactivity; expiration is performed on the next received frame, without a background timer. A chunk received after eviction or expiry starts a new transfer, so callers must retry complete objects and cannot use this cache as durable replay protection. Up to 512 encoded frames can wait for serialized processing; excess frames are rejected and require retry. The caller must also manage channel lifetime and authenticated peer behavior.

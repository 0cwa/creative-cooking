# Current cooking projection candidate

`prepareCurrentCooking` creates a new Loro document only from an explicitly supplied recipe title and purchase values. It does not load or import the source document. The caller must derive those values from an authorized, frozen current source, validate its admission and source delegation, and verify recipient identities. This narrow schema matches the current runtime, not the eventual complete cooking domain.

The injected provider must generate and securely persist an independently random key, return an opaque reference, and authenticate the full context when wrapping it to each authenticated recipient. The test provider seals a payload containing the key and complete context with libsodium sealed boxes and is evidence of the fresh-key boundary, not a production provider or a complete context-bound package protocol. A generated key may be orphaned after a preparation failure; the provider must garbage collect unpublished keys without deleting keys referenced by durable publications.

Preparation does not authorize publication or release. A durable admission needs a single transaction that compares the accepted authority revision and commits the validated child, the fresh document, its generation and epoch, recipient-encrypted key packages, outbox identities, and pending old-generation edit classifications. The current authority CAS writes only its authority record; a separate document commit is not atomic with it. Until that extension exists, this module must not publish or release keys. After a successful atomic commit, release already persisted bytes; after failure or restart, inspect durable state before retrying. Never import old-generation Loro operations into the fresh document. Preserve those edits for semantic rebase or explicit review. Retain old branches and keys under their existing access rules.

The decoded Loro history and unwrapped recipient-key test checks a deleted-content canary, personal-data canary and old key material. It does not prove the full schema or any network delivery, pairing ceremony, human identity, runtime crypto selection or native interoperability.

# Atomic projection publication: contract and remaining integration

Affected invariant: an admitted successor must not become active or release a newcomer key unless its verified current-only projection, successor authority and release queue are durable together. The existing `compareAndSwapPairingAuthority` changes only one opaque authority record; `commitLocal` cannot atomically replace that record. Running either first leaves a crash window. Storage transactions must remain the shared SQLite and IndexedDB runners.

Proposed additive `publishProjection` input: a versioned, bounded operation ID; the complete expected household authority precondition (revision, selected parent and snapshot); the validated next authority record; fresh document ID, generation and snapshot bytes with an absence precondition; immutable recipient-encrypted key package IDs and bytes with exact recipient IDs; outbox rows referencing those packages; and immutable references to all old-generation pending edits requiring rebase or explicit review. Bind the input to one admission and current-state grant, selected source checkpoint, delegation and projection manifest. The authority caller must verify every signature, source restriction, cryptographic package, ceremony and possession proof before invoking storage; storage checks structure and transactional consistency, not human identity. Exact policy and package byte schemas must be frozen with C1.

The transaction first resolves operation identity. An exact completed retry returns the saved result; any different reuse is a conflict. For a new operation it compares the actual authority record with every expected field, requires the next revision to increment exactly once, requires the new document and package identities to be unused, and writes the successor record, document, manifest, encrypted packages, outbox rows, pending-edit references and operation result together. Any conflict or failure writes nothing. Records and references must be checked on replay, so partial damage is corruption rather than success. Read APIs must return copied durable bytes and allow restart recovery before retransmission. Do not publish or transmit a merely prepared projection. A successful commit permits retransmission only after current-authority reauthorization. It does not itself prove peer receipt.

The structural transaction is implemented as `ProjectionAtomicStorage.publishProjection` and `getProjectionPublication`; the household authority precondition, new authority, fresh documents, encrypted packages/outbox, wrapped local data-key record, manifest and old-edit references commit together. Exact retries return the original publication; inconsistent records fail closed. The transaction requires a previously authenticated master catalog and does not verify signatures or human confirmation.

The current candidate has no real independent out-of-band human verifier, complete fresh signing and wrapping-key possession proof, accepted current-state delegation verifier, secure durable key provider, or C1 encoding. These are concrete evidence and provider requirements, not approval to substitute callback booleans or a cast to `Verified`. Until those exist, admission and key release remain pending even when the signed parent quorum is valid. The old-generation edit references must preserve original bytes and effect IDs; automatic raw CRDT history import is prohibited. Test the extension on both runners with faults after every write, reopen, exact retry, changed retry, stale authority, reused package, and concurrent successor publication.

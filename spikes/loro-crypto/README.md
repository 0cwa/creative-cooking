# K1 primitive probes

Exploratory component tests only; not a production suite, pairing protocol, audited application, or complete recovery package. RFC 8032 and RFC 7748 fixed vectors check raw Ed25519 and X25519 bytes. The fixed XChaCha fixture is generated by this implementation and checks runtime consistency, not independent correctness. The X25519/HKDF envelope is a primitive interoperability probe and does not authenticate the sender or constitute an approved pairing scheme.

Run `npm ci`, `agent-heavy -- npm test`, then `agent-heavy -- npm run bundle` here. Serve this directory with `agent-heavy -- python3 -m http.server 18765 --bind 127.0.0.1` and open the page in an isolated T3 browser profile. Await `window.probeResult`; rejection or displayed stack is failure. No identity, extension, clipboard, persistent storage, or remote service is involved. The local browser and Node results do not establish Hermes compatibility. Delete the generated bundle after testing.

The fixture uses random keys for authenticated wrapping and tests a one-holder envelope separately from 2-of-3 Shamir. Shamir does not authenticate shares: this probe checks the reconstructed key by opening the envelope. This is not a complete package format: holder uniqueness, metadata authentication per share, scope/audience rules, replay protection, and threshold validation require implementation. The hardcoded fixture context is not a canonical production encoding. No provider credentials appear in fixtures. Never use fixed keys or nonces from this probe in production.

Native Hermes execution, Expo secure RNG integration, cross-device exchanges, additional malformed input checks, and an authenticated pairing construction remain unproven. No claim is made that these component probes approve a pairing design. Noble 2.4.0, Shamir 0.0.4 and esbuild 0.25.12 are pinned in the isolated lockfile.

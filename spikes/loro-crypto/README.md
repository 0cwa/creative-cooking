# K1 crypto fixture

This is an isolated interoperability experiment, not a production crypto suite or approved pairing implementation. Node and browser use `libsodium-wrappers` 0.7.15; the Expo entry uses the named exports of `react-native-libsodium` 1.7.0. Both expose `crypto_box_seal` and `crypto_box_seal_open`. Sealed boxes provide recipient confidentiality and integrity, not sender identity. The fixed Node- and browser-generated ciphertexts use a public test seed; each runtime opens both. Sealed encryption is randomized. RFC 8032 and 7748 vectors independently test Ed25519 and X25519. The XChaCha and recovery vectors are implementation-generated cross-runtime checks, not independent correctness evidence. Secret fixtures and keys are public test data.

The bounded ceremony fixture hashes an ordered JSON tuple containing both key bundles, nonces, roles, household, action, parent and ordered signaling messages. It requires the same out-of-band commitment twice, both role-specific signatures, signed acknowledgements of encrypted challenges, a possession hook, an authority hook and a one-time persistence hook before returning a simulated release decision. Its hooks are fixtures, not proof of human identity, authority, atomic persistence, real QR transfer or replay protection. No dataset key is released. The composition needs a separate security review; do not use this JSON encoding as a production contract. Existing product authorization and real transport remain integration work.

Personal recovery probes separately model one-holder authenticated key envelopes and threshold shares; envelope AAD binds owner, scope, generation, threshold, holder count, holder and index, and the encrypted payload authenticates the ordered holder list and reconstructed key. The tests check wrong owner, scope, generation, key, holder index, duplicate/insufficient holders and payload corruption. This is not a finished production package format or a shared-key assistance grant. Shamir shares have no intrinsic integrity; authentication is supplied by the envelopes and encrypted payload.

From this directory: `agent-heavy --mem 1G -- npm ci --prefer-offline --no-audit --no-fund`, `agent-heavy --mem 1G -- npm test`, and `agent-heavy --mem 1G -- npm run bundle`. Run `agent-heavy --mem 512M -- python3 -m http.server 18765 --bind 127.0.0.1`, open the page in an isolated T3 browser profile and await `window.probeResult`. No user identity, extension, clipboard, persistent storage or remote service is involved. Close the tab and stop the server afterward.

## Native reservation pending

The isolated Expo Router entry installs `expo-crypto`'s `getRandomValues` adapter before importing shared tests and displays/logs `K1_RESULT` or `K1_FAILURE`. It refuses remote-debug mode; it does not use Expo's `getRandomBytes` development fallback. Metro resolution, JSI linkage, native RNG and execution are not yet verified. On this host the SDK path is supplied to the host process because the host execution bridge does not preserve the sandbox SDK environment. The native app has its own package name and should not access app data. Once S1 grants the reservation, run `agent-disk-check` before the potentially large build, then from this directory run `agent-heavy -- npm run native:prebuild` and `agent-heavy -- env ANDROID_HOME=/home/x/Android/Sdk ANDROID_SDK_ROOT=/home/x/Android/Sdk npm run native:assemble`. Install the resulting APK using the permitted Android installation tooling. Open the reserved emulator with a new T3 `device_open` session and use its bound command for launch and UI inspection. Capture `K1_RESULT`, platform and exact build variants, verify release and exchange newly produced ciphertext both ways before claiming Hermes interoperability. Never run `expo run:android`, which can launch the device outside the bound device session. Build output and local dependencies are disposable.

The installed SDK 57 tree reported six npm advisories (three high and three moderate) and an optional worklets peer warning on 2026-11-17. Investigate before any production adoption. Runtime and security claims remain subject to C1 selection and independent protocol review.

For a fresh browser exchange, call `await window.k1Exchange("seal")` in the test browser and add the resulting public test ciphertext to `FIXED_BOXES` before bundling the native build. The native result contains `sealed.generatedBox`; pass that hex to `await window.k1Exchange("open", hex)` in the browser. These are fixture keys only. Call device_list to check the device state, and device_open if it needs to be reopened.” twice, including after list and reopen.
